# Prompts

Bazooka runs no AI of its own (settings `ai_mode = "agent"`). Connected agents (Piyush's Grok bot, Instinct, any MCP or REST client) do the thinking and LinkedIn research, and save results in the **bazooka-v3** format.

| What | Lives in | Used by |
|---|---|---|
| Agent guide (`/AGENTS.md`, also `/` for agents asking for markdown) | Generated by `api/_lib/agents-md.js` from `api/_lib/schema-v3.js` and `api/_lib/tools.js` | Every agent, read once |
| The bazooka-v3 format and its checks | `api/_lib/schema-v3.js` | Tool input schemas, the checks before saving, the field reference in AGENTS.md |
| MCP server instructions | `api/mcp.js` → `INSTRUCTIONS` | Sent to every MCP client on `initialize` |
| LinkedIn search prompts | `settings.search_prompts` (Admin → Agent prompts) | Returned filled in by `get_company`; listed in AGENTS.md |
| Message guides (six) | `templates` table (Admin → Agent prompts) | Returned by `get_company`; the agent writes the message from them |
| Connect message for a new agent | `admin.html` → `connectMessage()` | Admin copies it into the agent with its token |

## Design choices
- **One save, one transaction.** `save_conversation` stores the transcript, company, founders, needs, people, follow-ups and private note together (`save_v3` in Postgres), or nothing at all.
- **Checks, not AI.** Bad input is refused with an exact list of what to fix; the agent fixes and resends.
- **Only what was asked.** People may only be saved for a type the company needs; at most 3 open suggestions per type; research people need a LinkedIn link.
- **Private stays private.** `private_note` is stored for people only and never returned to agents.
- **Retries are safe.** The same `external_id` returns the first result.

## The old server-side AI (switched off)
`api/_lib/prompts.js`, `capture.js`, `llm.js`, `autofill.js` and the `capture-v2` prompt are kept but unused. `/api/ingest` and `/api/autofill` answer 410 unless an admin turns Bazooka's own AI back on in Admin → Agent prompts.
